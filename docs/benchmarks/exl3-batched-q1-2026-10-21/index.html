Counter-window boundary qualification

A post-capture strict audit found a leading sample that still contained the final prefill publication in one native C4-4K window. The report applies the same deterministic final committed-prefill plateau rule to every original window in both implementations, then applies the unchanged occupancy, reset, integer-round and exact token-conservation checks. Only leading samples before that plateau are removed; the endpoint is unchanged and is never searched to obtain preferred throughput or residual. Native uses its live actual-computed counter for the activity plateau; Python uses its live prompt counter, which the pinned source updates on first prefill output. Python’s actual-computed histogram is published only when a request finishes, so it cannot guard an in-flight window. Its independent actual-computed histogram remains the prefill-throughput metric; no prompt-minus-hit inference replaces it.
